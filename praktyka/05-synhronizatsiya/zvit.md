## 4. Причини виникнення помилок

### Місце 1. Неатомарне оновлення лічильника

Операція на зразок:

```python
x.value = x.value + 1
```

складається з трьох окремих дій:

1. Читання поточного значення.
2. Обчислення нового значення.
3. Запис результату.

Якщо два процеси одночасно прочитають однакове значення, вони можуть записати однаковий результат замість двох послідовних оновлень. Це призводить до втрати оновлень і порушення балансу між відвантаженим товаром та залишком.

### Місце 2. Гонка між перевіркою та списанням

У початковому коді спочатку перевіряється умова:

```python
if zalyshok.value >= kilkist:
```

а потім виконується списання:

```python
zalyshok.value -= kilkist
```

Між цими діями інший процес може змінити залишок. Через це кілька процесів можуть прийняти рішення на основі застарілого значення, а після списання залишок може стати від'ємним.

### Чому інваріанти порушуються з різною частотою?

Баланс порушується через втрату оновлень спільних лічильників і невідповідність між відвантаженням та залишком. Для від'ємного залишку потрібен конкретний збіг у часі між перевіркою доступності товару та його списанням. Тому баланс порушувався в кожному початковому прогоні, а від'ємний залишок виник не завжди.

## 5. Виправлення програми

Для синхронізації процесів було створено спільне блокування:

```python
zamok = mp.Lock()
```

Об'єкт `zamok` передається кожному процесу. Блокування охоплює перевірку залишку та всі пов'язані оновлення:

```python
with zamok:
    if zalyshok.value >= kilkist:
        zalyshok.value -= kilkist
        vidvantazheno.value += kilkist
        moi += kilkist
    else:
        vidmov.value += 1
```

Блокування захищає всю критичну секцію, а не лише окрему операцію запису. Це забезпечує узгоджене виконання перевірки та зміни спільних даних. Водночас генерація випадкової кількості товару для замовлення та інша робота поза критичною секцією не потребують блокування.

Після додавання спільного блокування `zamok` усі 10 прогонів із початковим навантаженням і всі 10 прогонів зі збільшеним навантаженням завершилися без порушень перевірених інваріантів. Експеримент підтвердив ефективність блокування критичної секції для забезпечення узгодженості спільних даних у перевірених умовах.
